# VC 投资评估评分卡

本评分卡用于 AI 产品、AI 基础设施、开源项目和早期创业公司的投资评估。

## 宏观门槛

打分前先回答三个问题。任何关键问题失败，都可以直接 Pass。

| 问题 | 通过信号 | 失败信号 |
| --- | --- | --- |
| 细分领域是否仍在机会窗口期？ | 没有单一玩家垄断，或目标项目本身可能成为新标准 | 目标项目没有可信差异化，心智和生态已被占满 |
| 结构性优势是否存在？ | 开源治理、社区飞轮、数据/生态/标准控制、分发优势 | 只是包装层、prompt 工程、没有可积累资产 |
| AI 周期价值溢价是否适用？ | 位于推理、训练数据、评估、RAG、Agent 工具链、AI 元数据治理等结构性卡点 | 只是旧 SaaS 加 AI 功能 |

## 五维度评分

| 维度 | 权重 | 核心问题 |
| --- | --- | --- |
| A. 开源生态与社区健康度 | 25% | 项目是否有真实、可持续、非虚荣的社区采用？ |
| B. 团队与全球化能力 | 20% | 团队是否同时具备工程深度和全球商业触达？ |
| C. 技术护城河与市场定位 | 20% | 技术是否有差异化，能否成为细分事实标准？ |
| D. 商业化路径与 PMF | 20% | 收入质量、客户质量和商业化路径是否成立？ |
| E. 退出路径 | 15% | 是否存在可信的战略并购、IPO 或后续融资路径？ |

总分公式：

```text
总分 = A*0.25 + B*0.20 + C*0.20 + D*0.20 + E*0.15
```

## A. 开源生态与社区健康度

优先看键盘指标，不要只看 GitHub Stars。

强信号：

- 生产依赖仓库多。
- 月活贡献者多。
- 外部贡献者占比高。
- PR 合并延迟低。
- Issue 关闭率高。
- 发布节奏稳定。
- 有 ADOPTERS.md 或命名企业用户。
- 有 ASF、CNCF、LF、PyTorch Foundation 等治理或背书。

弱信号：

- Stars 高但贡献者少。
- 外部贡献者很少。
- issue 长期无人处理。
- 没有生产采用证据。

One-Vote Veto：

- 外部贡献者占比低于 5%，且项目声称自己是开源生态型公司。

## B. 团队与全球化能力

强信号：

- 创始人有可验证的开源贡献历史。
- 是相关栈的 committer、PMC 成员或重要维护者。
- 有顶级论文、可复现 benchmark 或基础设施公司经验。
- 英语文档和国际社区从第一天存在。
- 有美国企业试点、付费客户或全球 VC/企业网络。

弱信号：

- 只有公司仓库贡献。
- 学术强但商业执行弱。
- 全部客户、文档、社区都局限在单一国家。

One-Vote Veto：

- 公司仓库外零可验证工程贡献历史。

## C. 技术护城河与市场定位

技术层级：

| 层级 | 描述 | 投资含义 |
| --- | --- | --- |
| L1 | 新算法或新架构 | 最强护城河 |
| L2 | 已知方法上的重大工程创新 | 强护城河 |
| L3 | 差异化系统集成或工具链 | 中等护城河 |
| L4 | prompt 工程或简单微调包装 | 通常 Pass |

强信号：

- 有独立 benchmark。
- 竞品、云厂商、硬件厂商需要兼容它。
- 有机会成为事实标准。
- 厂商中立带来企业采购偏好。

One-Vote Veto：

- 核心产品只是 L4 prompt/微调包装，没有底层差异化。
- 24 个月内叙事转型 3 次以上。

## D. 商业化路径与 PMF

收入质量从高到低：

1. 产品 ARR / 订阅。
2. 按使用/API 计费。
3. 基础设施嵌入 / OEM 许可。
4. 专有数据、模型资产、评测资产货币化。
5. 专业服务。
6. 赠款、LoI、MOU。

强信号：

- 有产品 ARR。
- 有美国或全球企业客户。
- inbound pipeline 来自社区或产品使用。
- 最大客户集中度不过高。
- 产品毛利率健康。

风险信号：

- 收入完全未验证。
- 专业服务收入主导且没有产品化路径。
- 单客户收入集中度过高。
- 估值显著高于证据质量。

One-Vote Veto：

- 收入完全是 LoI/MOU，且当前估值高于行业中位数 2 倍以上。

## E. 退出路径

强信号：

- 项目可能成为某细分领域的事实标准。
- 有 2 个以上明确潜在战略买家。
- 买家存在“必须拥有，否则竞争对手拥有”的紧迫感。
- 有 IPO 路径：规模、增长、品类领导、治理成熟。

弱信号：

- 只能人才并购。
- 买家可轻易 fork 或内部复刻。
- 项目没有控制点，只有功能点。

## 决策阈值

| 分数 | 判定 | 行动 |
| --- | --- | --- |
| 8.5-10.0 | 强烈推荐 | 快通道 IC，推进条款 |
| 7.0-8.4 | 有条件推荐 | 附里程碑或补 DD 后推进 |
| 5.5-6.9 | 观察/跟踪 | 加入 pipeline，设定 3-6 个月触发器 |
| <5.5 | Pass | 记录拒绝原因 |

One-Vote Veto 覆盖总分。
