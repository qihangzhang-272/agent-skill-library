# 写作流程详解

本文档是交互式写作流程中四个步骤的详细展开。SKILL.md 中的流程概要已足够日常使用；当需要更多指引或遇到卡点时，打开本文档。

## Step 1: SCQA Framing（框架搭设）

### 目的

在动笔前和 Qihang 对齐文章的地基。SCQA 强制你从一个具体的紧张状态出发，而不是从一个"有趣的话题"。如果没有 C（冲突），就没有必要写文章。如果没有 Q（问题），文章就是信息列表。

### 四个要素的详细定义

**S (Situation) — 这个领域公认的背景是什么？**
- 不是"AI 时代来了"这种废话。具体情况：谁说了什么、什么时候、多少人在讨论
- 让一个不熟悉这个领域的人看五秒钟就能进入状态

**C (Conflict) — 什么疼痛、变化或反直觉现象出现了？**
- 关键判断标准：这个冲突能不能在不讲任何"应该怎么做"的情况下说出来
- 如果 C 是"AI 让写作效率降低了"，那是垃圾。如果 C 是"Steinberger 说你不要再写 prompt 了，Cherny 说他也不要了，这两个人是工具的开发者"，那可以聊
- 最好的 C 是具有启发性的矛盾本身，不需要你的观点去赋予它价值

**Q (Question) — 文章必须回答的核心问题是什么？**
- 这个问题不应该是一个 rhetorical question（明知故问）
- 好问题：你写的时候自己也不确定答案
- 坏问题：答案已经在问题里了（"AI 真的在改变写作吗？"）

**A (Answer/Hypothesis) — 你的初步核心论点是什么？**
- 先有观点，再找证据。不要漫无目的地列举信息
- 即使你的最终文章是"我不知道"，也必须有一个你在探索的假设方向

### 检查清单
- [ ] S 足够具体吗？（有名字、有时间、有事件）
- [ ] C 能独立站立吗？（不需要你的判断它就是一个矛盾）
- [ ] Q 是你真的在问的问题吗？（不是 rhetorical question）
- [ ] A 是你的观点吗？（不是"这是一个有趣的话题"）

## Step 2: Logic Tree Decomposition（逻辑树分解）

### 目的

将核心假设分解为 3-5 个一级支撑论点。每个论点应该符合 MECE：互相排斥（Mutually Exclusive）、整体穷尽（Collectively Exhaustive）。

### MECE 原则

**互相排斥：** 每个论点在概念上不重叠。如果两个论点用了同一组证据，它们就没有被充分分开。

**整体穷尽：** 所有论点加在一起覆盖了核心假设的全部范围。如果有明显缺口，树就不完整。

### 对每个论点，预设这三样东西

1. **这是什么**（定义层）——这部分论证的断言是什么
2. **为什么它成立**（推演层）——演绎推理或归纳证据
3. **它意味着什么**（判断层）——即使这个论点成立，这指向了什么更大的东西

### 每个论点需要的证据类型（提前标注）
- 需要哪类数据？（引文、推文互动数、源码行数、时间线对比）
- 需要哪个案例？（某个具体的人做了什么、某个具体的产品做了什么）
- 需要什么对比？（"以前是这样，现在是那样"）

---

## Step 3: Deepening and Validation（深化与验证）

### 目的

对每个支撑论点，深层展开。这一阶段产出的是"读者看不到的研究工作"——不能每一段推演都变成文章段落，但你需要知道每一条想法的支撑结构。

### 深化模板

**对每个论点，完成以下三个句子的填空：**

1. **为什么它发生**（演绎推理）
   - 大前提是 ____
   - 小前提是 ____
   - 所以 ____

2. **证据**（归纳推理）
   - 案例 1：____ （具体的人、具体的时间、具体的行为）
   - 案例 2：____
   - 数据：____（如果有的话）

3. **判断或对策**
   - 这对理解这个领域意味着 ____
   - 但它也有一个局限/边界/未知是 ____

### 验证

向 Qihang 呈现核心推理链。问："逻辑是否成立？有没有感觉弱或缺失的东西？"

**不要在确认之前开始写。** 这个步骤如果跳过了，写出来的东西就会在某些薄弱的地方坍塌。

---

## Step 4: Pyramid Output（金字塔输出）

### 目的

将所有东西整合成一篇完整的文章。

### 输出结构

**标题：** 必须有抓人感，包含核心价值或张力。

**开头：** SCQA 故事化引入。不要写成"最近 X 发了一篇文章"——从问题出发，不是从引用出发。

**正文：**
- 每个主要章节一个子标题
- 子标题下第一句是核心句子（这一节要讲的）
- 然后展开详细信息
- 每个主要章节附带一个内联配图建议

**结尾：** 重开问题。不要用格言关闭。

### 配图建议格式

```
[📷 配图建议：这里放 X 的截图/生成图，承接上文的 Y 论证点，视觉上突出 Z]
```

一个好配图建议一次性回答三个问题：
- **什么图？** 推文截图 / 产品页面 / 生成概念图 / 源材料中的图示
- **服务于哪个论点？** 它桥接一个刚刚落地的具体断言和读者的心理图像
- **图上应该视觉上突出什么？** 数据点、对比、规模、人物、张力

**规则：**
- 永远不要把配图建议当作软弱写作的拐杖。文字必须自己承载论证
- 每个主要章节或关键的转折点一个配图建议；不要每隔两段就铺一张
- 只建议在调研文件夹中真实存在的图片，或人类能从描述中想象出来的生成概念图。不要虚构从未捕获的截图
- 配图建议用中文写，和草稿语言保持一致。它们保持内联；不要抽出来放在单独的附录里

### 字数

公众号文章默认至少 5000 中文字符。除非 Qihang 只要求提纲。

### 交付

写完草稿后，简要说明所做的主要结构和风格选择。
