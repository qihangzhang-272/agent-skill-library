# 启航头像角色·内容讲述与配图

本文件沉淀启航公众号的角色身份、内容参与与配图语法。启航头像是原创公众号生成型视觉的默认身份资产，无需逐篇指定。这里属于 `editorial-visual-storytelling` 的视觉判断层，负责人物如何帮助读者理解内容；当前 Host 按本技能产出的 visual plan 调用指定的 Baoyu Owner，不在交接时另行改写角色、文案或关系。用户当前要求优先。

## 默认加载规则

- `cover`、`illustration`、`comic` 与 `single-panel explainer comic` 默认加载本角色参考图，并在 visual plan 中写清角色动作。
- `infographic` 与 `diagram` 仍优先保证信息清晰；适合加入讲解入口时使用头像角色，不适合时只继承当前已确认的配色与笔触。作者当前采用原版 PPT 的白／浅底、深蓝文字和钴蓝重点，具体参考见 [公开视觉参考](public-visual-sources.md)。
- `source reuse` 不加入角色，不覆盖转载原图、研究截图、产品界面、论文图表或真实证据。
- 用户明确指定其他角色、其他品牌身份或无人画面时，遵循用户要求，并在 visual plan 记录覆盖原因。
- 下游渲染技能不得因为提示词中没有再次出现“使用启航头像”，就退回通用人物；角色参考由本默认规则自动继承。

## 角色身份参考

优先直接参考：`../assets/qihang-avatar-character.jpg`。原件缺失或迁移宿主时，按 [公开视觉参考](public-visual-sources.md) 的固定公开 JPEG 链接与哈希恢复；它与已用原头像字节一致，不依赖旧电脑路径。

这张图承担人物身份与原生墨线参考，不把暖纸背景、周围标语或头像构图当作整篇视觉。页面风格按当前已确认的 PPT 样页，素材用途分别声明。项目明确指定的原头像优先；生成前实际查看并直接传入，不只给文字描述。后续角色图至少保留：

- 年轻男性动漫形象，深蓝近黑的蓬松乱发。
- 大号棱角透明框眼镜，神态由当前场景决定。
- 深海军蓝猫图案上衣、白色 `?!` 标记与钴蓝高光；保留自然肤色。
- 身边可出现一只小型黑鸟，作为追问、反应或观察伙伴；不要求每张图都出现。
- 黑色粗细不匀的手绘线条与钴蓝涂抹，不改成光滑 3D、标准企业扁平人或通用日漫男主。

禁止把角色替换为圆框眼镜、整齐短发、商务衬衫的通用“研究员”。那会保留颜色，却丢掉人物身份。

固定同一张脸、年龄感、头身比例、发型、眼镜与服装设计，包括参考图可见的衣服标记。动作、自然表情、视线、景别、位置和场景可以变化。未确认的新生成图只作候选，不能取代原头像成为身份真源。

## 内容参与与文章节奏

用户已于 2026-09-06 明确认可课堂及多学习情境新版，并说明“这种场景化的配图才是我要的东西”。这确立文章情境优先的长期方向；不固定学生题材、三场景数量或本篇插图节奏。对应可执行提示结构与局部修图方法见相邻 baoyu-image-gen 包的 `references/contextual-illustration.md`。

先写清：**这段在说什么，前后论述如何变化，用什么情境才能让读者看见这个意思？** 答案写入已有 `Position`、`Viewer job` 与 `Human/material anchor`。确定场景关系后，再在 `Character anchor` 中安排头像的身份、动作、景别与尺度。

| 段落关系与读者需要 | 情境如何表达 | 可选形式 |
| --- | --- | --- |
| 比较不同的人、方法或条件 | 多个具体情境并置，靠行为和环境看见差异；同等选项不画成顺序或排名 | 多场景插图；必要时单幅讲解漫画 |
| 看懂组件、流程、因果或反馈 | 先明确节点与关系，再选择是否由角色操作关键位置 | 关系讲解图；精确结构使用 diagram |
| 理解过程中的阻力与变化 | 同一对象跨格延续，用动作、视角或材料状态变化推进理解 | 知识漫画 |
| 获得代入、停顿或阅读愉悦 | 环境、人物互动或物件特写承担感受，角色可小、可局部出现 | 场景插图 |

角色可做提问者、演示者、核验者或观察者，由内容决定，不塑造成永远正确的老师。伙伴可共同观察、递材料或发现异常，不机械插科打诨，也不替作者增加态度。

检验两件事：把头像临时想成普通参与者，场景仍应能表达段落意思；把整张图拿走，读者是否少了一次有价值的理解、比较或停顿？不要为了证明 IP 有用，强迫他主持、解释或占据大半画面。

不同学生适合不同方法，可以把听讲、独自阅读、与 AI 讨论融在一张图里；头像只是其中一位学生，其他学生有独立外貌。只有正文确实讲同一个人的前后过程时，才重复同一角色。多人共享原生墨线画风，不等于共享同一张脸。

多图根据正文节奏改变景别、人物尺度、信息密度或表达方式。保持角色和笔触一致，不等于重复同一个半身像加气泡。用户要试效果时，先固定段落意思与插入位置，再比较情境如何讲述它，并把候选放回正文联读；不先列一组 IP 形式让文章适配。不设每段一图、每篇四种形式或固定口头禅。

## 丰富但可读

一个观看任务不等于只能有一个人物、一个场景或一个视觉中心。允许多个同等情境、前景材料、中景动作与背景空间；共同主线由段落关系形成。细节承担语境、关系或阅读趣味，必要环境不能被“简单背景”的通用生成默认值删掉。

- 角色可进入关系中央、俯身操作或从局部特写进入，不固定站在图边上。
- 关系图先明确问题、必要节点、方向和例外，再安排角色。框、箭头和分组可表达真实关系；禁止的是没有语义的连线网络。
- 标签和连线区域保持干净；角色与场景延续粗墨线和钴蓝笔触。
- 连续漫画一般 2–4 格，每格一个动作；同一课本、便签或对象保持连贯。
- 场景图允许更丰富，保留视线落点与留白；不机械堆深夜、咖啡或杂乱桌面。

## 单幅讲解图的可选构图

当正文需要亲民解释一段逻辑、而架构图过冷或概念插画过虚时，优先评估 `single-panel explainer comic`；不再以用户是否主动提到头像作为触发条件：

```text
中央：一段关系或判断的视觉中心
侧边：头像角色做一个明确动作
文字：气泡、原文短语与读懂本图所需的解释、条件
图外：补充说明和可点击来源
```

上面是一种适用构图，不是所有配图的固定模板。关系和角色动作决定最终位置。

## 画面职责

### 中央逻辑视觉

- 只回答一个 `Viewer job`。
- 通过聚散、大小、共同参与、选择、替换、核验等可见关系讲清逻辑。
- 可以出现简洁图标、分组与有明确语义的箭头；不堆无关组件框、仪表盘和多层卡片。
- 关系必须来自正文，不得先重新总结出一套新名词再生图。

### 头像角色

每个场景先有一个可辨认的主要动作；一张多场景图可以有不同人物的不同动作。按语义选用，例如：

- **指出**：告诉读者先看哪里。
- **追问**：把正文中的关键问题说出来。
- **核验**：检查来源、权限、记录或结果。
- **选择**：在多个能力中挑出当前任务需要的部分。
- **退后观察**：让中央关系成为主角。

不要连续使用托腮、皱眉、灵光一现、竖大拇指或演讲姿势。小黑伙伴可以承担惊讶、疑问、递标签或看向异常点的动作，减少人物自说自话。

## 文案规则

1. 标签从当前确认的正文取短语，不绑定某个草稿文件名。对白可由视觉编辑根据正文动作撰写，不得冒充作者逐字引语或增加观点。按 `visual-copy-desk.md` 先审候选，再确定 `Exact text`。
2. 场景标签与对白以识别物件、补语境和推动动作为准，不凑固定字数或标签数量；解释图保留独立读懂所需的完整定义、例子、关系与条件。
3. 图内稿与构图说明分开，列出全部 `Exact text`。`No other text` 只禁止未批准的额外文字，不能删掉已经确定的必要解释；不让模型二次概括。
4. 可编辑的文章长段正文留在 HTML；图片内需要的标题、标签、对白与解释由图像模型直接生成。图外补充说明和必要来源，不自动展示制作回执或核验入口。
5. 中文错字或多余文字返回已有图像生成工具局部编辑或重新生成，不得用 SVG、Canvas、Pillow 或图片覆盖修补。

## 公众号构图

- 默认 4:3 横图，适合正文手机宽度；封面仍由 cover 技能单独判断。
- 人物尺度随场景和阅读任务决定，不给整篇预设头像占比。单幅讲解图可以突出角色；全景、并列情境和物件特写通常让环境或关系占更多空间。
- 人物位置随动作决定；视线与操作对象对应，不遮挡主标签。
- 单幅讲解图缩到 375px 宽时，关系、人物动作和必要短话仍清楚；无字场景则检查动作与视觉重心。

## 提示词骨架

当前公众号 PPT 风格的输入结构、三类实际案例和封面局部修图见 [已认可配图案例与提示词](approved-wechat-ppt-prompts.md)。先提供本段具体意思、人物动作、使用材料与情境关系，再分别声明身份／风格／证据参考，最后列出定稿文字。新图与修图的参考图顺序可能不同，按实际用途说明；不重复保留另一份旧暖纸色模板。

## 交付检查

- 角色是否仍能被认作头像里的人，而不是同色系陌生人？
- 需要解释关系时，是否真的讲清一段正文逻辑？
- 去掉气泡后，画面关系是否仍然成立？
- 先看场景能否表达段落意思，再看头像身份；不能靠“像本人”弥补内容空泛。人物动作和环境是否对应这个插入位置？
- 所有文字是否来自 `Exact text`，且没有模型擅自添加？
- 形式是否完成本图的观看任务，且和相邻图片有必要的节奏变化？

## image2 执行与返工

- 使用责任 Skill 的原生生图接口，不新增 API 包装器，不把提示词中的模型名当作已验证的实际调用结果。
- 先保存完整 prompt。把成品布局、参考图用途、新动作与材料变化、必要关系、Exact text 分开写；原头像已经清楚时，不反复堆风格形容词。
- 多参考图分别声明用途：原头像锁身份与笔触，其他材料提供场景、关系或版式。修改候选时同时带原头像和待改图，只改发现的问题。
- 无参考输入能力时不能悄悄退回纯文字，并声称身份已锁定。
- 验收并排比较原头像的脸型、乱发、透明眼镜、服装、年龄感和墨线；配色相同不算通过。检查气泡归属、连线方向和全部文字。
- 身份漂移先修正对应部位并保留原头像；关系混乱先减少同时表达的内容；场景过空补有作用的细节，不能永远退回半身头像。
- 教学过程、概念或架构场景在 brief 与 QA 中记录示意性质，不冒充真实经历、界面或已验证结构。正文图注只按用户确认的内容描述，不自动追加“本号 AI 配图”等制作说明；不改动图片来源记录与平台原生声明。不得凭空增加组件、关系或成功保证。
- 记录失败与修正，不宣称提示词能保证百分之百一致。用户选定后再将候选用于正式文章；长期形式偏好只来自明确反馈。
