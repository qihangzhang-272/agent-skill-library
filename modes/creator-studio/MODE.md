# Creator Studio

面向公众号、X、长内容研究、视觉表达和发布准备的长期创作工作场。

## 适合做什么

公开信息与给定素材研究、真实账号案例调研、热点选题推荐、作者采访、口述整理、风格适配、视觉叙事、生图素材、配图与漫画、Markdown/HTML 排版、图片压缩、发布准备，以及基于已授权数据的内容复盘。用户可以提供大纲，也可以通过阅读素材后的聊天和采访提供观点，再由 AI 整理成文并交还用户修改。各项工作可以单独发生，不要求走完整链条。

## 会用到哪些资料

AI 先了解你的长期要求和可用技能，再按创作需要读取账号文章、草稿、历史反馈、参考文章和截图。

账号经营任务按需读取项目已有定位、栏目规划和发布反馈，由 `public-account-writing-style` 负责文章作用、读者收益、多平台改编与复盘判断；对标来源和经验的证据核对由 `topic-research-deposition` 负责。区分个人 IP 信任、传播与商业目标，不默认用单篇阅读量衡量所有内容。具体账号策略和逐篇数据留在项目。

公众号视觉任务按需读取当前项目 `.baoyu-skills/VISUAL_STYLE.md` 与责任 Skill 对应的 `.baoyu-skills/<skill>/EXTEND.md`；不把各技能的配置复制进 Mode。风格、角色和构图选择以本轮明确要求为先，其次是项目已确认配置，再按责任 Skill 的配置查找顺序读取用户级偏好，最后才使用技能默认值。项目明确不复用头像角色时，不因技能默认角色说明强行加入人物。此优先级不覆盖授权、安全和完成标准。

完整长图文的配图应尽量丰富。由 `editorial-visual-storytelling` 根据正文安排封面、真实材料、场景插图、漫画和必要的概念视觉，写清各图的插入位置与阅读作用，再由已有责任 Skill 生成；不能用几张资料预览代替用户明确要求的生图。丰富体现为有作用的情境、人物动作、景别与材料变化，不靠重复头像、装饰海报或固定每段一图凑数量。当前已确认视觉基准改为作者开源 `ai-native-teaching-kit` 的原版 PPT，替代旧头像海报与整幅暖纸漫画的默认：先实际查看适用样页，学习清晰标题、充分解释、白色或浅底、淡彩留白、少量钴蓝手绘重点及真实素材与角色的关系，不把头像本身当作完整风格。使用角色时提供本次允许的直接参考，让动作服务解释；不要求每图出场。场景服从作者正文，不能虚构经历或把假说画成已证实机制。跨电脑恢复头像与 PPT 样页时读取责任 Skill 的[公开视觉参考](../../skills/editorial-visual-storytelling/references/public-visual-sources.md)；制作时按需读取[已认可配图案例与提示词](../../skills/editorial-visual-storytelling/references/approved-wechat-ppt-prompts.md)，分别使用身份、风格和证据素材，不复制案例的固定文案或图数。

调用作者开源原版 [build-visual-teaching](../../skills/build-visual-teaching/SKILL.md)，复用材料先行、素材组织、视觉基准、原像素融合与最终验收方法；原包及引用文件保持不变，来源版本见 [接入与偏好记录](../../feedback/2026-10-05-creator-studio-teaching-visual.md)。先按文章主张整理来源、版本、原文件、说明作用、使用位置和权利边界，再给生图最小完整输入。内容与不可改变的术语、数字先确定；视觉层只生成周围画面并留出证据区；原生排版层放回真实素材像素、准确文字和可点击来源。详细方法直接读取它的 `references/material-integration.md`、`visual-benchmarks.md` 及 `delivery-qa.md`，不复制成第二份技能。官方截图、原图、书页和证据不得由生图重画；生成图中文字错误返回生图修正，准确正文与来源优先原生排版。此处媒介是公众号与 X 长图文，不因此新造课程、重写作者结构或额外输出 PPT；交付验收落实到最终图片、正式 HTML、两种宽度预览及真实平台回看。

公众号排版沿用 `qihang-wechat-layout` 的个人样式目录：`qihang-editorial`、钴蓝 `#2447D8`、刊头双线、编号底线标题及已确认的引用、强调和列表形式。具体参数继续由责任 Skill 与项目配置维护；不另存一份样式。正式微信 HTML 与 677px／375px 发布前只读预览共用同一渲染真源，检查层级、字号、留白、图片、图注、行内对勾和横向溢出；预览不加入调样式控件。公众号写入优先调用 Baoyu 原生 API CLI，保留原稿、正式 HTML、只读预览和真实平台回执。

公众号成品的重点呈现由AI主动配齐：按定稿选择粗体、同蓝色系高亮、波浪下划线和段落分隔，保留原词与限定，不等待作者逐个指定，也不按配额堆满组件。调用排版技能的[编辑呈现约定](../../skills/qihang-wechat-layout/references/editorial-presentation.md)，清除给执行者看的制作回执和核验入口，保留必要来源署名；检查实际HTML与平台入口的样式一致性。此偏好已由作者确认，本地效果认可与微信编辑器技术验收仍分别记录。

作者启动文章发布交付时，默认同时整理公众号与 X 完整长图文，并在已明确授权范围内同步公开发布；用户本线程确认的双平台要求持续复用，不重复索取同一授权。两端沿用同一份作者确认稿，保留完整内容与同一视觉身份，平台差异只影响比例、排版与链接呈现。已公开的同篇 X 文章优先更新现有文章，先查重，不重复发一篇。只有两端均完成实际发布与回看，才报告双平台发布完成；平台草稿、本地预览、公众号公开发布和群发分别记录。遇到质量门禁、登录、额度或平台能力缺口，继续完成可执行部分并报告具体状态，不把单端成功当作同步完成，也不自行创建定时发布任务。

## 技能怎么配合

围绕这次创作选择研究、写作、配图和排版技能。材料齐全时可以直接编辑或排版；只需要一张图时，就处理图像任务。

个人 IP 的采访写作使用 GitHub 上的 `ArcBlock/agent-skills` 原版 `interview-writer`。完整原包保持不变；来源、适用性和核验记录见 [采访协作记录](../../feedback/2026-10-03-creator-studio-interview-workflow.md)。采访由它辅助提问，研究由 `agent-reach`、`topic-research-deposition` 和 `known-content-archive` 提供资料；文章整理由 `public-account-writing-style` 承接，中文轻度润色使用库中实际名称为 `humanizer-zh` 的技能。具体分工和用户边界由本 Mode 组织，不写回任何技能原文。

在用户启动个人 IP 采访写作时，按以下协作方式推进：

1. AI 查证当前 AI 领域热点，给出候选选题、发生日期、来源链接和可讨论之处，交给用户选择。推荐主题不等于替用户决定立场；用户也可以提出自己的题目。
2. 选题确定后，AI 提供可实际阅读的原文、必要背景和截图，区分来源事实与解释。先让用户阅读，不把 AI 摘要冒充原材料，也不在用户尚未选择时直接成稿。
3. 用户阅读后与 AI 聊天。调用 `interview-writer` 连续采访，通常每次围绕一个问题，根据刚才的回答继续追问，不把采访变成问卷、方案审讯或预设答案的展示。已有答案直接复用；用户观点不能靠旧画像推断后当作本次回答。
4. 原始问答和口述单独保留。围绕用户实际说出的观点、例子和表达组织文章；采访材料可以形成文章结构，不要求用户再另写一份书面大纲。需要补事实时返回研究，缺少观点时继续问，不替作者补立场或经历。
5. `humanizer-zh` 在整理稿上做轻度编辑：去除无意义的口水词、重复和不顺畅表达，保留作者常用词、语气、比喻、态度与原有言语。承载犹豫、限定或立场的“我觉得”“可能”等不能当作口水词删除；已经自然的句子不改。原声、整理稿和润色稿保留对照，交给用户修改。
6. 用户修订确认的同一份内容用于公众号图文或贴图，以及 X 完整长文。中英文适配保留同一观点和证据；平台差异只影响排版、图片比例和呈现，不自动压缩成 280 字短帖，也不为不同平台重写作者立场。
7. 素材获取、截屏、归档、打包、生图、概念视觉、漫画、排版和平台草稿核验由 AI 完成，沿用最新确认的匿名 IP、原版 PPT 视觉基准与个人排版约定。公开发布仍按用户授权和平台既有检查执行。

调用原版 `interview-writer` 时，以本次用户口述和明确意见为准。其默认观点、默认思考模式和默认文风不能冒充用户画像；不因上游默认行为读取无关私人背景、自动改写全局画像、增加新闻稿或替用户选题。实际采访材料留在当前项目；只有用户明确确认的长期偏好才进入长期记录。原包的采访轮次和短帖输出示例不覆盖本 Mode 的连续采访、原声保留和双平台长文要求。

作者上下文沿用 ASL 原生的 Profile、Mode 与 Case 边界，由当前 Host 按任务读取和执行，不新增画像加载器。跨 Mode 且用户明确确认的精简长期偏好保存在当前活动 Environment 的 [PROFILE.md](../../PROFILE.md)，随原生投影提供给 Host；仅适用于采访写作的协作方式与创作偏好留在本 Mode。具体文章的观点、经历、原始问答和证据保存在用户选定的创作项目，沿用当前 Case 的材料与产物位置，按需提供给 `interview-writer`。单次口述不自动升级成长期画像；用户明确要求长期复用时，再按影响范围沉淀到 Profile 或 Mode，不把整篇问答复制进长期上下文。

`workspaces/writing/.asl/profile/` 的旧工作区骨架不作为当前 Mode 的活动画像入口，也不把历史 `.asl/runs/<run>/artifacts/` 当作当前 Harness 的默认运行目录。现有空骨架保留，不自动迁入、补写或填写作者观点。不读取技能包自带或宿主全局的兜底画像，不创建 `~/.claude/content-profile/` 等宿主专有画像目录；原生资料不足时保留未知，继续采访，不用默认模板填补。四类画像所需的作者上下文由实际资料提供，不要求先创建四份占位文件。

## 开始前需要确认

本 Mode 不自动进入产品投资判断、估值或尽调。外部发布、登录、私人数据读取和破坏性覆盖必须得到当轮明确授权。受第三方许可限制的 Skill 继续遵守自身 `SOURCE.md` 与许可边界。

人机写作边界：AI 可以研究热点、推荐主题、准备可读素材和连续采访；选题由用户决定，核心观点、个人判断、经历和最终改稿来自用户。AI 可以把实际采访问答、口述或用户大纲组织成文章，再交回用户修改，不必先索取另一份详实大纲。整理与扩充限于这些输入和已核查资料，不能凭空起草核心论点、冒充亲历或用自己的看法填补作者观点。网络素材、素材整理、内容截图、风格适配、视觉、生图素材、配图、排版与检查由 AI 承担。已有明确意见和授权直接复用。

表达与润色：内部研究可以严谨核查，但文章不默认呈现成定义、环境拆解和逻辑编号的推理报告。结构和节奏以用户口述、大纲与原稿为准；不强塞竞争解释、逻辑清单、框架选择、自评分或未经用户表达的核心观点。中文整理稿需要润色时按需使用 `humanizer-zh`，保留立场、事实、否定、条件、时间、归因和确定程度，已经自然的句子可以不改。它是编辑指导，不能证明作者身份或保证 AI 检测结果。英文适配保留同一含义和证据，不机械套用中文模式。

匿名 IP：任何公开文章、推文、图片、截图、视频、下载包与链接都不得泄露用户真实姓名、身份、履历、机构、地址、联系方式、客户或私人材料，也不能通过仓库账号、提交作者、截图路径、文件名、元数据、二维码和跳转链接反查身份。只使用本轮已明确可公开的信息；无法确认的身份关联素材不进入公开版本。已确认的原创动漫 IP 角色可以继续用于匿名内容；匿名要求不等于弃用角色或改成通用人物。生成前实际查看并直接引用原头像，执行已有情境、涂鸦漫画与个人样式要求，去掉实名水印及可反查链接。项目介绍先核对项目背景、实际设计、交互与验收证据，不把设想写成成果。用户要求进入平台草稿箱时，以实际保存后回看为完成；本地文案、排版预览、平台草稿与公开发布分别记录状态。可以沿用匿名身份，不虚构资历或业绩。具体内容和发布决定仍由用户保留。

公众号发布准备必须经过 ContentAny 的实际检测与编辑复核。用户指定最终拟发布整稿的 AI 指数必须在 0%–20%（含 20%）内，超过 20% 禁止发布；未取得有效指数也不得放行。其他质量建议可以有依据地采纳、部分采纳或不采纳，但不能用编辑判断豁免数值门槛，实质质量问题仍须解决。门禁契约由 `baoyu-post-to-wechat/references/contentany-gate.md` 维护；它与排版预览、发布授权并列，不能互相替代，也不让普通研究、写作讨论必须先调用检测工具。

## 会得到什么，如何改进

可以得到候选热点、可阅读素材、原始采访问答、保留原声的文章整理稿、润色稿、视觉方案、配图、漫画、排版文件和双平台发布准备。用户已有大纲时仍可直接扩充，不重复采访；原始材料与编辑版本保留对照，用户修改确认后准备交付。具体账号事实和逐篇反馈留在项目。发现相关外部技能时，完整保留上游内容，只在 Mode 中组织职责、交接和用户边界；升级前检查上游差异，不自行改写技能，不自动发布或上传。
