# Diagram Clarity For WeChat

公众号架构图的任务是让非专业读者看懂一个关系，不是保存完整系统模型。

## 先写问题

每张图先写一句自然语言问题：

- 好：第一版生成以后，工作去了哪里？
- 差：AI 写作链完整架构。

问题决定视图。不能回答同一个问题的节点不进图。

## 一个视图，一个抽象层级

借鉴 C4 的 abstraction-first 思路：

- 面向普通读者，只展示参与者和主关系。
- 面向执行人员，再展示步骤或组件。
- 不在同一张图里同时画“研究—写作—排版”的宏观阶段和每个阶段的内部动作。

## 公众号默认复杂度

- 主要节点优先 3–5 个；超过 6 个先拆图。
- 只保留一个主阅读方向。
- 关系类型默认一种；必要时增加一种虚线反馈。
- 每个节点只放名称；说明移到图注。
- 同一层节点保持相同语法。面向普通读者优先用可见动作：`读材料`、`逐页核对`，少用 `判断`、`治理`、`赋能` 等抽象名词。
- 子区域不超过两个。
- 没有必要时不画图例、编号、技术标签和装饰图标。

## 推荐源格式

1. 简单流程、关系、状态：优先 Mermaid 源 + 自动布局 + 主题化 SVG。
2. 需要多视图的软件架构：参考 C4 / Structurizr，将模型和视图分开。
3. 特殊自由构图：才使用手写 SVG。

在 wechat-writing 中，`baoyu-diagram` 默认保留 `.mmd`、`.svg` 与 `@2x.png`。公众号只引用 PNG，源文件留在过程包。

## 清晰编辑主题

- Background: `#F7F2E8`
- Foreground: `#101827`
- Surface: `#FFFDFC`
- Border: `#CDD4DF`
- Accent: `#2447D8`
- Human decision accent: `#E98A3A`
- Muted: `#667085`

色调继承头像的编辑感，但节点、连线和文字保持几何清晰。不要默认添加纸张噪点、涂鸦箭头或手写字体。

## 节点文案检查

1. 把节点逐个念出来，能否听出主语正在做什么？
2. 是否混用了对象、动作和结论，例如“材料 / 生成 / 人的判断 / 价值沉淀”？
3. 是否为了对称而使用四个抽象名词？
4. 删除图形后，这些标签是否只剩一组文章小标题？

不合格时先改文案，不靠图标和颜色补可读性。
