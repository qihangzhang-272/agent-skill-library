# 技能图编排

## 定义

技能图记作 `G=(V,E)`：

- `V` 是可独立调用的瓦技能。
- `E` 是带标签的材料依赖，例如“研究事实包”“定稿 Markdown”“视觉 brief”。
- 边不表示状态流转，也不授予下游修改上游产物的权力。

线性 chain 是每个节点最多只有一个主要前驱和后继的特殊图。存在分支、汇合、可跳过节点或反馈时，优先写 graph。

## 运行时增量构图

graph 文件定义可用能力与材料接口，不预先决定整次任务会走哪些节点。运行时维护的是当前材料集合，而不是固定步骤状态：用户的一句话、一次讨论、一个链接、已有草稿、研究包和生成资产都可以成为材料。

每轮只做一次局部选择：

1. 明确用户此刻要推进的结果，以及阻塞它的一个主要缺口。
2. 判断是否真的需要技能；普通讨论、局部写作或直接回答能够完成时，不为留下调用记录而硬用技能。
3. 只从当前环境真实可发现的技能中，选择输入已满足且产物能直接缩小缺口的一个或少数几个技能；没有真实技能时经 skill-index 查找，不能编造节点名。
4. 技能完成后把产物并回材料集合，再根据新情况决定下一步；不得在任务开始时把所有潜在节点排成自动执行清单。
5. 用户补充想法、否定方向或给出新材料时，立即更新目标与材料集合，旧的候选路径自动失效。

隐式选择技能时，在 commentary 中轻量说明，不默认生成状态文件：

```text
[技能调用：domain:skill-name]
原因：当前缺口
输入：本轮实际材料
预期产物：将补回材料集合的内容
```

只有用户要求审计，或任务存在必须追溯的外部副作用时，才把实际调用过的技能记录进既有回执或过程文件；不为此新建通用 `skill-trace.md`。

## 节点契约

每个节点至少能回答：

1. 接受哪些真实材料；哪些只是可选上下文。
2. 产生什么可验证产物。
3. 是否有外部副作用或授权要求。
4. 哪些失败需要回到哪个材料 owner，而不是由 orchestrator 代填。

瓦技能可以列常见相邻节点，但不负责路由，也不能假设自己必然位于某个 workflow 中。

## 运行规则

1. 从用户即时目标和当前材料选择下一段最小子图，不默认跑全图，也不预先锁定后续路径。
2. 只对本轮已选择且确有依赖的节点排序；互不依赖并且同时有用的节点才并行。
3. 已存在产物先验证，验证通过即复用，不为补步骤编号而重做。
4. 反馈边必须有停止条件，例如“事实缺口补齐”或“移动端无溢出”。
5. 发布、删除、付费生成等副作用是授权闸门，不是普通材料边。
6. 只保存跨节点有价值或需要审计的产物；单瓦技能任务不强制生成完整过程包。

## 图文件位置

正式图放在：

`plugins/orchestrator/skills/workflow-orchestrator/references/graphs/<name>.md`

使用 `assets/graph-template.md`。修改后同步 `docs/workflows/`、升级 orchestrator 版本，并运行仓库两项验证。

## 不做什么

- 不新增“图调度器”或领域二级 orchestrator。
- 不把节点判断复制进图定义。
- 不用固定状态文件证明节点“跑过”；以产物及其验证结果为准。
- 不把所有可能技能都挂进一张大图；按稳定目标拆图。
- 不把能力池的展示顺序当成默认执行顺序。
