# 讲解结构与深度取舍

## 总领、展开与回收

整课交代问题和学习路径，模块说明职责，概念先给平实定义；展开后回到听众可作的选择、使用或判断。模块概览可融入引入页，不机械增加页面或要求成品写出“总分总”。

先用文字说明关系，再选图形：分工可并列，包含用范围，调用标明发起方与对象，数据流标明传递内容，替代保留分支，反馈才画闭环。混合关系用标签或线型区分；不要把不同层级概念与产品例子串成必然演进路径。简单单点说明不必画复杂关系图。

从材料与关系解释选择会改变什么、瓶颈在哪、哪些部件可替换、什么条件下该用另一方案。区分来源结论、教学归纳与讲者观点，后者缺失时按主文的材料准备关口处理。

## 分配页面、讲稿与补充材料

- 页面保留定义、关键因果、读懂原图所需标签与必要边界；文字承担解释与结论，图片呈现界面、状态、关系或结果
- 充分解释、具体例子与自然过渡可放页面或讲稿；承载不下就拆页，不删成三句口号
- 重复证明、无关版本争论与长实现细节按需要放补充材料或不采用
- 通识以听懂“是什么、为什么有用、怎么开始、基本边界”为准；明确要求专业实作时，正文包含必要代码、运行过程与失败分析

例如通识 TDD：解释先将期望行为变成可检查测试，再按 Red → Green → Refactor 实现并整理；补充测试只覆盖被检查行为，不保证所有目标正确。到此即可，不主动展开逐行调试。专业课按目标加深。

## 介绍 Skill 时保持具体

说明实际问题、原文规则与资源、调用时机、输入输出、子技能分工及前提限制。保留有辨识度的关键原句、术语、顺序和条件，补中文释义；用可追溯案例解释规则与结果，不凭空宣称作品由它生成、已经测试或一定更好。自制关系图标“据原文整理”，不能标“官方原图”。

## 自然过渡与范围控制

讲稿用可直接说出口的第一人称承接前文，再说明下一段为何出现。例如：“前面看了设计怎样变成网页，接下来讲怎样把功能接起来，并检查修改有没有破坏原来的行为。”不要编造“我长期用”“我最喜欢”或未提供的经历。

介绍人物或来源时先说明选材理由和维度。核对语音转写中的人名、产品名与书名。本次课程的受众、产品、范围与页数只用于本次任务：讲 AI 工作环境概念不擅自转向神经网络实现，历史通识要求也不能限制未来专业课。

## 自足示例：把“截图能证明什么”讲清

以下是新编教学示例，不是某个产品的真实实验记录。

1. 总领：“截图要能支持页面上的判断。”解释一张图能展示某个入口或状态，却未必证明功能覆盖范围、速度或质量。先问：“它具体支持哪一句话？”
2. 展开：并列“图上看得见”与“还不能推出”。前者包括可辨识的按钮、状态和版本标记；后者包括所有账号都可用、长期稳定或所有场景效果相同。使用自制示意界面并标明“示意”，或使用有权使用的真实截图。
3. 回收：“一句主张对应一处可辨识证据；证据之外的判断单独说明依据。”边界是截图过时或裁切丢失条件时，需要更新证据或缩小主张。转场：“接下来讨论怎样把截图放进页面，既看得清，又不丢上下文。”

页面保留上述核心解释与边界，讲稿补充提问和具体场景。内容超出一页容量时拆页，不把完整解释缩成三个标签。
