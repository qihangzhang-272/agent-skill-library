# 项目目的

本仓库是个人使用的 Agent 运行能力库。

它的目标不是整理资料，而是沉淀可复用的 Agent 工作能力：当一个新项目启动时，agent 能根据项目类型选择合适技能、来源索引、调用链和配置参考，再把需要的能力配置到项目中。

## 第一原则

- 调用链清楚比技能数量多更重要。
- 技能收录要回答来源、用途、触发场景、适用边界、验证方式和是否进入 Linear。
- 外部技能默认先做索引；只有许可证、复用价值和边界清楚时，才把技能包迁入 `skills/`。
- 网站 prompt 只做入口索引，不复制正文。
- UI 库源码不复制，只记录使用场景和配置参考。
- 一次性实验不进入正式技能库，只保留实验结论或调用链判断。

## 仓库角色

| 目录 | 角色 |
| --- | --- |
| `skills/` | 启航自培养技能包，以及启航维护的轻量外部 repo 索引 |
| `catalog/` | 机器可读总账：技能、来源、状态、触发场景、迁移边界 |
| `docs/` | 治理规则、收录流程、组合搭配、调用链 |
| `local-experiments/` | 本地实验，不进入正式库 |

## 外部资料边界

本仓库不绑定任何单一外部知识库、Obsidian vault、Notion workspace 或历史项目目录。

如果某个技能来自一个本地目录，它只是导入 provenance，不代表本仓库和那个目录存在长期关系。本仓库只记录“这个能力是否值得复用、如何调用、如何配置到新项目”。

## 当前主线

- 写作发布：服务于 topic -> writing -> md2wechat 的公众号链路。
- 产品分析：服务于 product-analysis 的端到端链路，并按输出模式进入 analysis-only、visual-report、investment-report 或 oss-investment。
- 技术 / 开发范式：服务于文档驱动、评估充分、可稳定交付的端到端开发管线。
- 运营：服务于技能库治理、Linear 跟踪、GitHub 私有仓库维护和自动化协作。
