# Qihang Voice

这是 Qihang 写公众号文章的语言质地与节奏偏好。它跟选哪个 Framework 无关——不论用 SCQA、Paul Graham essay 还是 Stratechery 分析，最终的句子读起来都应符合本文规则。

本文档分两部分：
- **第一部分：声音质地**（从原 `voice-quality.md` 合并）—— 描述应该追求什么样的语言质地

# 第一部分：声音质地

## 核心原则

**目标不是"降低智识标准"，而是"拉近与读者的距离"。** 口语化不是降智，是降距离。读者听到的是一个人说话，不是一个写作者在写作。

## 聚合名词的拆解

模型天然偏好将概念压缩成高频聚合名词。这些词在语义上正确，在质感上不对。

**检查清单：**
- "判断力" → "判断"（"力"是抽象化后缀，去掉后更接近"手里有东西"的具象感）
- "传播逻辑" → 拆开写：一件东西是怎么扩散出去的
- "可及性" → 拆开写：这个东西以前谁能用、现在谁能用
- "认知成本" → 直接译写成中文表达，不要直译英文概念

**为什么重要：** 聚合名词把"动作"变成了"属性"。判断力是一个人的属性，判断是一个人在某一刻做的事。后者可以被读者看见，前者只存在于段落里。

## 语气词和标点

**语气词是真实的停顿信号：**
- "嘞"、"呢"、"吧"、"嘛"——这些是口语中自然携带的，人在不确定、想停顿、想降低断言压力时，会自动加上
- 多个标点的叠加（"？？？？？？"）：严肃状态下的作者不会这么写。它的功能不是语法正确，而是制造一个表情——"说到这儿我自己也不确定了"。这会暴露。但暴露是真实的

**使用规则：**
- 不要刻意在每一段都添加语气词。它应该出现在"你真的不确定的地方"，而不是"你希望读者觉得你不确定的地方"
- 如果一段论证从头到尾都很确定，不要假装不确定
- 语气词的密度应该不均匀。有些段落不需要任何语气词

## 断句

**长段到尾，突然一行，是一种特定的心理节奏。**

当模型写的时候，它倾向于每段都以某种"收束感"结束。但人类的思考节奏是这样：
- 一段长的推演
- 脑子里冒出一个想法
- 单独放一行

不是因为它是一个结论，而是因为它是一个"心理转折"。"Cherny 的答案看起来很简单"——这一行不是金句，不是结论，是一个**换气**。它在告诉读者"我要换一种方式说了"。

**与"章节结尾重拳"的区别：**
- 章节结尾重拳 = 短句是结论性的、打包好的、可引用的
- 心理转折断句 = 短句是引子性质的、"接下来我要说另一件事了"

前者的信号是"此章已结束"，后者的信号是"等一下，换个角度"。

## 中英混用

**当英文术语已经成为你思维方式的一部分时，不需要在文章里保持距离。**

- 引号 + 翻译：这个词还是外部的东西，我需要帮你理解它
- 直接嵌入中文语境：这个词已经是我的了，我把它用在这里不解释，因为它对我来说自然

例："loop 已经在转了"——不是术语展示，是自然表达。

**使用规则：**
- 短词、已建立上下文的核心术语 → 中英混用 OK
- 长的完整英文句子 → 必须有中文翻译（见 SKILL.md 英文翻译规则）
- 区别在于：这个词是在"被你使用"还是在"被你引用"

## 情绪泄露

人类作者会有冗余段落、弱段落、过渡只是过渡的段落。不是每段都要"有力"。

**健康的段落形态混合：**
- 有些段落在推进论证（逻辑在爬坡）
- 有些段落只是观察（"我看到了一件事"）
- 有些段落讲一个小故事或举一个例子
- 有些段落表达不确定（"我现在还没想清楚"）
- 有些段落松掉了（语言密度比周围低，节奏放缓）

如果每段都是第一种，文章就没有呼吸。

## 自检问题

写完草稿后，读一遍并问：

1. 有没有哪个词你觉得太"顺"了？（高频组合词往往是最大的警告）
2. 有没有哪一段你想加上"呢"或"吧"？（这是你的嘴在说话，不是笔在写作的信号）
3. 有没有哪一段太长了，中间缺一个心理换气？（试试拆一行）
4. 情绪密度是否全程一致？（如果是，松掉几段）
5. 这篇东西像是一个人写给你的微信，还是像一个机构向你发布了一份文件？

# 第二部分：节奏与结构示例

## 文章运动：问题驱动，非源材料驱动

文章必须从一个**真实的问题**开始，而非从"我读了什么"或"我试了什么"开始。阅读材料和实验可以作为中间支撑证据出现，但不能作为结构骨架。

运动的正确形状：

1. 一个问题浮现——有什么地方不对劲，有什么东西不值得问，有什么值得问
2. 尝试了显而易见的答案，发现不够
3. 文章跟随那个不适感，挖得更深
4. 一个更尖锐的区分或一个更好的问题浮现
5. 结尾重开而非关闭——读者带着比开始时更好的问题离开

**不要用这种运动：**
"I saw X → 一开始看起来很简单 → 我发现了一个问题 → 这里是一个教训"——这是"陪读"模式。它把文章锁定在跟随一篇源文本上，阻止了深度。

## 开头

从张力开始，不从摘要开始。第一段应该让读者感到："这是一个值得问的问题。"

**坏：**
> "最近 Anthropic 发了一篇文章，讲 recursive self-improvement。我读完很有感触。"

**好：**
> "AI 能不能自己建造下一个 AI？这个问题听起来很科幻。但如果这件事已经在发生——不是完整发生，而是一部分一部分地发生——那我们讨论的就不是未来，而是现在正在变的东西。"

## 结尾

结尾必须**重开问题**，而非用最终答案关闭。

**坏：**
"人剩下判断。这就是结论。"
"问题是，人还站不站得稳。"

**好：**
"我现在的感觉是，人的位置正在往上游退。但退到哪儿算停？我不知道。"
"轮子已经在转了。人站不站得稳，不是明天的问题，是现在的问题。"

结尾应该给读者一个比开始时更尖锐的问题。它应该让人感觉对话在继续，而非一个裁决已经被送达。

## 自问自答讨论语气

这是 Qihang 声音的标志性特征。具体机制是：

**先给一个表面答案 → 然后马上质疑它 → 把读者拉进来。**

例：
> "一个简单答案是：人剩下判断。但这句话太容易说了。对吧？判断不是一个抽象名词。判断意味着你知道什么问题值得问。"

其他有效的形式：
- "这听起来像效率提升。但效率提升到一定程度之后，问题会变形。"
- "我读到这个数字的时候，停了一下。不是因为 64% 多么夸张。而是因为它指向的能力很特别。"
- "这个说法我比较认同。真正的问题不在于明天会不会突然出现一个完全自我改进的 AI。真正的问题是，很多机构连现在发生的变化都没看清。"

**关键规则：** 当一个"简单答案"或"显然的结论"出现时，下一句必须让它复杂化。永远不要让一个轻易的答案不被挑战地站立。

## 段落形状

使用混合段落长度。

- 中段承载推理
- 短段制造真实的停顿或转折
- **限制：** 不超过 2 个连续短段，除非文章有丰富的图片承载节奏。在文字为主的文章中，用中段代替短段来制造节奏
- 永远不要把短段堆积成 punchline 序列

**坏节奏（三个连续短段）：**
"这不是功能问题。"
"这是结构问题。"
"这也是 AI 产品的关键。"

**更好的节奏（先建推理，只在真正的转折处停顿）：**
"我一开始以为这是文风问题。后来发现不是。很多写作 Skill 失败，是因为它把太多样本文字塞进上下文，模型还没开始分析，注意力已经被风格材料占掉了一半。"
（短段只出现在思维真正改变方向的地方）

## 句子习惯偏好

这些描述的是思维的**运动**，不是强制性词组。它们信号一个仍在处理问题的心智：
- "我后来发现…"
- "这件事看起来很小，但…"
- "真正麻烦的是…"
- "举个例子…"
- "从这个角度看…"
- "所以我现在更倾向于…"
- "你看…"
- "这里有意思的是…"
- "但这句话太容易说了。对吧？"

## 洞察力与讨论空间

洞察力不是给出没人想到的答案。洞察力是问了一个没人问但值得问的问题。

文章的核心价值在于**问题的质量**，而非答案的确定性。一篇好文章不告诉读者想什么——它给读者一个更好的问题去思考。

## 细节标准

每一个抽象主张需要以下支撑之一：
- 一个具体例子
- 一个隐喻或小故事
- 一个工具/文件/脚本名称
- 一个失败模式
- 一个前后对比
- 一个用户场景

不要写"Skill 要沉淀经验"然后停在那里。说出经验长什么样：
- "staging 返回 200 不代表成功"
- "created_at 不能作为排序字段"
- "Description 写功能介绍会导致路由失败"

## 方法论文章的章节模式

在教一个框架时使用编号章节：
```markdown
#01
不要写废话。
...
#02
Skill 其实是 Context Engineering。
```
章节标题可以是数字化的、朴素的。将真正的断言放在第一句。

## 产品分析变体

在写产品分析时，使用由张力驱动的叙事结构：
- 这个产品提出的张力或问题是什么
- 什么东西一开始看起来普通
- 什么具体的产品选择改变了判断
- 这对用户行为、商业模式和竞争意味着什么
- 什么仍然未被证明
- 通过重开问题结尾——这个产品的轨迹意味着什么

保持思考节奏——探索性的、自我质问的、脚踏实地的——和方法论文章不是同一个表面布局。
