# Visual Copy Desk

视觉文案先服从图片的阅读任务。封面可以用短标题，场景插图补语境、声音或关系；解释图需要完整讲清本图问题，保留必要背景、依据、顺序与条件，不能只留下文章观点的缩写。

## 参考原则

本文件吸收以下成熟内容规范的共同部分，不模仿品牌口吻，也不复制现成句子：

- GOV.UK：使用具体、日常、主动的语言，先考虑读者和任务。
- Microsoft Writing Style Guide：像说话一样写，尽快进入重点，每个词都要有用。
- GitHub Docs：清晰和意义高于形式一致；文案必须服从所在内容单元的语境。
- 18F Content Guide：文案帮助人完成任务，并通过清楚、诚实的表达建立信任。
- Reuters Standards：图片、图注、来源与实际发生的事情必须一致，不替图片虚构背景。

来源与边界见 `source-notes.md`。

## 先分清六种文案

下表长度是封面、场景插图、短标签与漫画气泡的参考；解释图的正文按本图问题和实际画幅安排，不套这些短文案字数。需要完整句子才能讲清的内容写入 `Exact text`。

| Copy role | 任务 | 默认长度 | 不该做什么 |
| --- | --- | --- | --- |
| `title` | 让读者知道这张封面或这一页在谈什么 | 每行 4–10 字，最多两行 | 同时写摘要和结论 |
| `caption` | 补充图片看不见的时间、身份、上下文或来源 | 1–2 句 | 描述“图中有一个人” |
| `label` | 帮助识别节点、物件或状态 | 2–8 字 | 写成一条小标题 |
| `narration` | 控制漫画的时间、距离或视角 | 每格 4–10 字短语 | 替角色总结论点 |
| `dialogue` | 让场景中的人物完成当前动作 | 每个气泡 4–10 字 | 借角色宣读文章提纲 |
| `none` | 让画面自己成立 | 0 字 | 因为空白焦虑而补金句 |

场景插图优先只使用一种主要文案角色。知识漫画可组合 `narration` 与少量 `dialogue`；解释图可用标题、正文和证据标注共同说明关系，避免重复层级挤占内容。

## 文字密度与审校

- 短标签、动作提示和气泡优先简短；封面分行以主题清楚、实际尺寸可读为准，长度建议不作为删信息的硬门槛。
- 解释图从文章与采用素材写明具体对象、动作、例子和条件：读哪份原材料，解释哪个概念或步骤，行动之后出现什么结果。保留作者判断与依据，不用整篇文章，也不能把这些信息换成“找材料、讲关系”等口号。
- 读取已有 [humanizer-zh](../../humanizer-zh/SKILL.md)，用原文和资料中的真实例子介绍对象、动作及原因，不能只换口吻或继续抽象概括，也不编例子或每图硬塞同一结构。修正实际图内稿的自然表达，同时保留独立信息、术语和限定。图内稿定下来之后再安排构图。
- 将全部定稿文字与构图、素材说明分开送入制作，不让生图模型二次概括或补写。长中文可用原生文字组装；拥挤先减装饰、缩小角色或分图。
- 补充说明和可点击来源可放图外，读懂本图所需的解释、条件和标签须保留在图内。

用户这次备课原文中的例子：只有“先找材料，再安排页面”，看不出材料拿来解释什么。可按原文展开为：“讲 Agent、Prompt、Context 时，先读原始资料，选能解释各部分职责与配合的原图和例子。页面要回答：一个任务进来后，这些部分分别做什么、怎样配合？”具体原图和职责再从本次实际资料核对，不能临场编出产品按钮、定义或作者操作经历。

## 四步文案工序

以下场景事实、留白和短句工序用于情境插图与漫画；解释图按上面的图内稿要求整理，不据此删除作者已给出的判断或必要正文。

### 1. 抄事实，不写观点

先写一句没有修辞的 `Scene fact`：

```text
初稿已经打印出来，作者正在对照原始材料删改。
```

不要先写：

```text
真正的判断发生在生成之后。
```

后一句是文章判断，不是画面事实。它会把任何视觉重新拉回金句海报。

### 2. 决定文字补什么

只能从四类缺口中选择一类：

- **时间**：这件事发生在什么时候、持续到哪一步？
- **语境**：为什么这个动作值得看？
- **声音**：此刻这个人真的会说什么？
- **关系**：图中两件事之间哪层关系无法单靠画面看懂？

如果没有缺口，选择 `none`。

### 3. 写三个不同角度的候选

三个候选必须改变信息角度，不能只是换同义词：

```text
事实：初稿已经出来，作者仍在逐页核对。

A｜时间：“初稿已经出来了。”
B｜动作：“我却还在一页页往回找。”
C｜留白：画内无字，图注交代核对动作。
```

### 4. 检查语境与可读性

1. **去图检查**：这句话离开图片后，是否变成一条随处可用的金句？如果是，重写。
2. **反复述检查**：图片已经清楚画出的动作，文字是否原样再说一次？如果是，删掉或补另一层。
3. **朗读检查**：让一个具体的人在当前场景里说出来，是否自然？若像演讲、翻译腔或品牌宣言，重写。
4. **可读性检查**：短文案是否易读；解释图是否在实际阅读尺寸保留充分解释，关系和条件能否独立看懂？不能因字数删掉独立信息。

## 各资产的文案方法

### 封面标题

- 保留文章真正的问题、人物或矛盾，不概括全文结构。
- 可以有悬念，但不能故意隐去主题制造点击。
- 避免“X 的本质”“从 X 到 Y”“重新定义 X”“为什么说 X 才是 Y”批量模板。
- 标题确定后，封面图不再叠加摘要、金句或三条卖点。

示例：

```text
差：AI 虚假繁荣与真实世界的鸿沟
可用：写完了，还在改
```

后一句只能在文章确实来自作者亲身修改经验时使用。

### 概念插图与图注

- 只承担情境或停顿的插图可无字；承担解释的图保留必要正文。
- 图注补时间、来源和画外信息，不做“如图所示”式复述。
- 使用具体名词和动词，少用“价值、赋能、判断力、范式、重构、沉淀、闭环”。

```text
差：判断力不可替代
可用图注：初稿完成后，作者把三份来源材料重新摊回桌上。
```

### 信息图与架构图标签

- 同一层节点使用一致语法：全是动作、全是对象或全是状态。
- 面向普通读者优先使用动作词，不使用系统内部名词。
- 节点名负责识别；读懂关系所需的方向、条件和限制放在图内相应位置，补充说明和可点击来源可放图注。

```text
差：材料 → AI 初稿 → 人的判断 → 写回 Skill
可用：读材料 → 先出一版 → 逐页核对 → 把规则补回 Skill
```

### 漫画旁白

- 一格旁白只控制时间、视角或未画出的信息。
- 连续三格不要写成三句长度相等、句式对称的排比。
- 允许第二格比第一格长，允许最后一格不升华。
- 第一人称只用于作者真实经历，不能为了“人味”虚构。

```text
差：
第一版很快。
费时间的是读、比、改。
规则来自做过之后。

可用：
初稿先出来
逐页找依据
再补一条规则
```

### 漫画对白

- 对白必须改变动作：提问、拒绝、确认、打断、承认不知道。
- 删除不会影响人物下一步动作的对白，通常只是观点装饰。

```text
差：“真正重要的是人的判断。”
可用：“这句的出处呢？”
```

## 中文视觉文案常见 AI 痕迹

- 每句话都能截成海报，却没有一句属于当前场景。
- 三句话字数相近、结构对称、结尾全部落句号。
- 抽象名词多，具体动作少。
- “不是……而是……”“真正的……”“从……到……”密集出现。
- 直接把文章小标题、配图建议或 `Viewer job` 搬进图片。
- 为了口语感机械加入“你看”“说白了”“其实”“原来”。
- 英文结构直译成中文，例如过多无主语被动句、名词化表达和连续定语。
- 每格都解释意义，没有人物在处理眼前的事情。

## 交付要求

`05.5-visual-plan.md` 的每项资产必须先记录：

1. `Scene fact`
2. `Copy role`
3. `Copy candidates`
4. `Exact text`
5. `Caption outside image`

短标签在 `Exact text` 后标注字符数；解释图保存全部审校定稿文字及其对应原文／素材。图后逐字对照定稿、逐关系对照原文；文案不足先修内容，错字、无关占位图或多余手臂另行修渲染。

下游生图 prompt 只读取 `Exact text`；图注只读取 `Caption outside image`。任何临时新增文字都视为失败。
