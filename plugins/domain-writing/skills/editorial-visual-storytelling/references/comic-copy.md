# Comic Copy For Public-Account Articles

知识漫画不是把文章切成若干结论。它必须让读者看见一个人、一个物件或一种关系发生变化。

## 分镜先写动作

每格先写可见动作，再写文字：

```text
错误：第二格解释“规则只能抓住已知问题”
正确：编辑删掉一句金句；下一版换了另一种句式回来
```

## 允许没有结论的格子

- 一格可以只是翻材料、停顿、等待或发现矛盾。
- 不要求每格推进一个论点。
- 最后一格可以留下仍需继续做的动作，不强制升华。

## 文案密度

- 一格优先只有一个 4–8 字短语或一个气泡，硬上限 10 个中文字符。
- 画面能表达的动作不再由字幕复述。
- 同一页不要同时使用标题、旁白、对白、标签和结论条。
- 对话必须像人在当前场景里会说的话，不像作者借角色讲提纲。
- 每格文字先标注 `Copy role`：`narration`、`dialogue` 或 `none`。
- 连续格子的旁白不要强行写成字数相近、句式对称的排比。

## 文案从场景中长出来

先写场景事实，再写人物此刻需要说的话：

```text
场景事实：编辑在初稿里看到一条没有来源的断言。
错误对白：“AI 能生成文字，但无法替代人的判断。”
可用对白：“这句的出处呢？”
```

前一句是文章论点；后一句会让人物继续查材料。对白只有影响下一步动作时才保留。

旁白只补画面看不见的时间、语境或视角，并压缩成快速短语：

```text
错误旁白：“她正在认真核对三份材料。”
可用旁白：“初稿出来了”
```

动作已经由画面承担，不需要字幕复述。

## 人类氛围从哪里来

- 手正在做什么。
- 人与材料的距离和姿势。
- 桌面上留下了什么。
- 角色忽略、删掉或重新拿起了什么。
- 时间和劳动如何被看见。

不要靠咖啡、深夜、皱眉或凌乱桌面单独伪造真实感；这些元素只有参与叙事时才使用。

## 避免四格公式

默认禁用：

1. 问题出现
2. AI 分析
3. 人类顿悟
4. 金句结论

如果四格可以直接替换成四个流程框，它还不是漫画。

## 与 Baoyu Comic 的边界

本文件与 `visual-copy-desk.md` 负责漫画的 `Viewer job`、动作、`Copy role`、候选文案、允许文字与情绪节奏。`baoyu-comic` 负责角色表、正式 storyboard、页面 prompt、角色一致性和图像生成。
