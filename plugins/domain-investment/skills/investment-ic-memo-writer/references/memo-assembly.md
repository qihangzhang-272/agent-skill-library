# IC Memo 组装方法

Memo Writer 必须逐份读完 01–09 的业务正文，再进行组装。它不重新研究、不建立新模型、不另选可比对象，也不凭偏好解决上游矛盾。

## 读取与缺口处理

- 先确认九份业务产物中实际提供了什么，不要只读摘要。
- 缺少运行上下文只做一次非阻断提示，不影响读取已有正文和继续成稿。
- 可补做的业务缺项要精确指出缺少的内容；无法取得的外部事实按未知项继续，并采用保守处理。
- Memo 只写业务正文；运行记录由工作区另存。

## 组装规则

- 开篇直给建议、理由、回报逻辑和最关键风险。
- 将事实、假设、判断、反证和未知项分别表达。
- 保留原始数字的日期、币种、单位、期间和情景；发现口径矛盾时说明其决策影响。
- 每个真实外部来源使用可读名称和可点击的 Markdown 链接；内部文件标识不能替代投资人来源。
- 专业术语首次出现时给出中文解释。
- 十三节都应有实质内容；表格只在提高比较效率时使用，不用占位数字填满版面。

## 结尾

只保留一个明确结论：`推进（Proceed）`、`有条件推进（Conditional proceed）`、`观察（Watch）` 或 `放弃（Pass）`。条件必须写明需要哪项证据或行动才能解除。
