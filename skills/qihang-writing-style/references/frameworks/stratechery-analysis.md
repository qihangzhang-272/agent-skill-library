# Stratechery Analysis（Ben Thompson 的战略分析法）

## 一句话概括

从一个**具体可观察的事件**（产品决策 / 收购 / 政策变动 / 财报数据）出发，追问"Why do businesses do what they do?"——通过分析**激励（incentives）**与**模式（patterns）**，提炼或调用一个**可复用框架**，然后用这个框架去扫多个真实案例，最后推导战略含义，并以一句 "It depends" 式的开放收尾。

这是一种"**单点观察 → 框架化 → 多案例验证**"的写作动作。它的特点是不停在描述层，而是要追问"激励结构变了什么"，并且**把答案做成一张可以复用到下一篇的图（map / spectrum / funnel / hierarchy）**。

## 信号（什么时候用这个）

- **信号 1**：题材是一家具体科技公司的具体动作（苹果改 App Store 规则 / Meta 砍 Reality Labs 预算 / OpenAI 推 ChatGPT Atlas / 某收购 / 某次财报里的数字突变）。
- **信号 2**：你已经有了"为什么这家公司这样做"的直觉，但想把它**升格成一个能解释其他案例**的模型，而不是只评论这一家。
- **信号 3**：你想写的题材天然带"**spectrum / 矩阵 / 漏斗 / 分层**"这类结构感（比如"差异化的供给 vs 同质化的供给"、"内部网络效应 vs 外部网络效应"、"做产品 vs 做平台"）。
- **信号 4**：你愿意在文章里**显式承认"It depends"**，不下绝对结论。你要的是给读者一把尺子，而不是一个判决。
- **反信号**：题材是单纯的资讯播报、事件复述、人物访谈、个人随笔；题材是工具讲解或方法论教学；题材是抒情或叙事故事——这些场景下"造一张框架图"会显得过度发力。

## 骨架步骤（6 步）

### Step 1: 从一个具体的可观察事件切入

- **这一步在做什么**：用一个**具体、可被读者立刻验证**的事件作为开头——一个产品决策、一次收购、一份财报数字、一则政策变动、一个 CEO 的公开发言。不要从抽象概念或宏观趋势开头。
- **关键判断标准**：开头第一段读完，读者应该能说出"哦，这篇是在分析 X 这件事"。如果你的开头是"近年来 AI 行业……"，那就是错的入口。
- **常见错误**：
  - 用"行业综述"代替"具体事件"。
  - 同时讲三件事，没有锚点。
- **加分动作**：Ben Thompson 经常用"我上周写过一篇文章，但我觉得不太满足"这种**主动承认前作不完整**的开场，把读者拉进自己的思考过程。

### Step 2: 追问激励重构

- **这一步在做什么**：核心提问是"**Why do businesses do what they do?**"——这家公司做这个动作，激励结构发生了什么变化？谁的动力变了？谁的成本变了？谁的护城河被削弱了？
- **关键判断标准**：你的解释要超越"他们想赚更多钱"这种废话。具体说出"这个动作把 X 角色从主动方变成了被动方"或者"这件事让 Y 的边际成本从有限变成了趋零"。
- **常见错误**：
  - 停留在道德判断（"这家公司在割韭菜"），没分析激励。
  - 只描述行为，没解释行为来自哪种结构性激励。
- **加分动作**：把激励变化用一个**反例对照**讲清——"如果激励没变，他们本应该做 A；现在他们做了 B，说明激励已经变了"。

### Step 3: 提炼或调用一个可复用框架

- **这一步在做什么**：把刚才看到的激励结构**抽象成一张图**。可以是一条 spectrum（光谱）、一个 2D 矩阵、一个漏斗、一个分层金字塔（如 Mobile's Hierarchy of Needs）。如果已有现成框架（Aggregation Theory / Funnel Framework / Moat Map），就直接调用；如果还没有，就**在这篇文章里造一个**，并给它起名字。
- **关键判断标准**：这张图必须有**两个以上的轴或维度**，且每个维度都有明确定义。读者光看图就应该能开始把别的公司套进去。
- **常见错误**：
  - 框架只有一个维度（这就只是一个清单，不是框架）。
  - 维度模糊，比如"好的 vs 不好的"——这种二分没有解释力。
- **加分动作**：给框架起一个**记得住的名字**（Funnel / Moat Map / Hierarchy of Needs），方便后续文章反复调用。Ben Thompson 之所以能十年内写出体系，是因为他每篇文章都在**积累工具箱**。

### Step 4: 用框架扫多个真实案例

- **这一步在做什么**：把 Apple / Google / Facebook / Amazon / Microsoft / Netflix / Uber 这些大家熟悉的公司**逐一塞进框架的不同位置**，看它们落在哪里、为什么落在那里。
- **关键判断标准**：至少 3 个案例，且其中要有一个**反例**——一个落在框架"危险区"或框架之外的公司（Ben Thompson 在 Moat Map 里用 Uber 作为"两边都不靠"的反例就是这个动作）。
- **常见错误**：
  - 只举正面案例，看起来框架万能（这反而让读者怀疑）。
  - 案例之间没有对比张力，只是平行罗列。
- **加分动作**：让案例的排序本身**讲一个故事**——比如从最纯粹的一端走到最纯粹的另一端，让读者沿着光谱走一遍。

### Step 5: 推导战略含义

- **这一步在做什么**：基于框架，回答"**这意味着哪些公司会赢，哪些会输**"。但不要给出绝对答案——要说明在框架里哪个位置是优势位置、哪个位置是危险位置，以及处在危险位置的公司**可以做什么动作**让自己迁移到优势位置。
- **关键判断标准**：你的战略含义要能被读者拿去用——他能用这把尺子去判断自己手里的另一家公司或自己正在做的产品。
- **常见错误**：
  - 含义太抽象（"未来属于平台型公司"——这是废话）。
  - 把含义说死了（"X 公司必将失败"——这会立刻让 Ben Thompson 风格塌掉）。
- **加分动作**：明确指出**框架本身的局限**——"在 supply-side 差异化的市场，这个框架成立；但如果监管介入，所有变量都得重写"。

### Step 6: 用一个 open question 收尾

- **这一步在做什么**：以一句 "It depends" 式的开放问句结束。Ben Thompson 最经典的收尾句之一就是 "as always, it depends." 框架不是判决书，而是一张可被新数据推翻的地图。
- **关键判断标准**：读者读完最后一段，应该想立刻拿这张图去套自己关注的下一家公司，而不是觉得"这事盖棺定论了"。
- **常见错误**：
  - 结尾给口号（"未来已来"）。
  - 结尾给绝对预言（"五年后 X 必死"）。
- **加分动作**：在结尾留下**两个让模型失效的场景**，邀请读者一起来想第三个。

## 一个完整例子

**原文来源**：Ben Thompson, *The Funnel Framework*, Stratechery, 2015-08-19
**链接**：https://stratechery.com/2015/the-funnel-framework/

**为何符合此框架**：这篇文章是 Ben Thompson 把"单点观察 → 提炼可复用框架 → 多案例扫描 → 战略含义 → 开放收尾"这套动作演示得最完整的一篇。它后来被反复引用，成为他战略写作的范式。

**节选 + 骨架标注**：

> **[Step 1 — 从一个具体可观察事件切入]**
> "For folks who weren't there, it's difficult to describe just how dominant Microsoft was at the end of the 20th century."
>
> 开头不讲抽象趋势，而是给一个具体锚点——20 世纪末的微软。Ben Thompson 接着补充微软统治了 23 年（1981–2004）。然后对比当下：Android 用户数最大，但远没有当年微软那样的统治力；Google、Facebook 用一套完全不同的机制成为巨头。读到这里，读者已经被锚定在一个清晰的问题上：**为什么这套"平台 + 生态"的旧模型解释不了新巨头？**

> **[Step 2 — 追问激励重构]**
> "the shift to Internet distribution and consumer markets meant a shift from scarcity to abundance."
>
> 这是整篇文章的激励重构核心：渠道从**稀缺**变成**丰裕**。在 PC 时代，发行渠道有限，平台锁定可以放大；到了开放互联网，**"being the best is a first order concern"**——做到最好不再是锦上添花，而是首要前提。一句话之内，他把整个竞争结构的底层激励重写了。

> **[Step 3 — 提炼可复用框架（Funnel Framework）]**
> Ben Thompson 在这里抽象出一个三列表：
>
> | 产品聚焦（Product Focus）| 捕获什么（Captures）| 漏斗指向（Funnels To）|
> |---|---|---|
> | Apple：极致 UX | 用户的付费意愿 | Apple 自身与开发者 |
> | Google：极致搜索 | 高动机用户 | 直接营销商 |
> | Facebook：与用户个人相关的内容 | 用户注意力 | 直接 + 品牌营销商 |
>
> 核心洞察："distribution and access is no longer the means of control but the end result."——**渠道与触达不再是控制手段，而是结果**。先做出超额体验，再用这个体验把某一类客户漏斗化沉淀下来。框架明确有两个维度（公司用什么产品聚焦 / 漏斗最终通向谁），并被命名为 Funnel Framework。

> **[Step 4 — 用框架扫多个案例]**
> 接下来 Ben Thompson 让这个漏斗扫过多个完全不同的行业，验证它的通用性：
> - "Taxis used to dominate because they owned distribution; Uber delivered a superior user experience."
> - "Hotels used to dominate because they owned supply; Airbnb delivered superior value."
> - "Newspapers used to dominate because they had geographic dominance"（→ BuzzFeed）
> - "Broadcast channels used to dominate because they owned the airwaves"（→ Netflix）
> - "LINE and WeChat are leveraging that by pushing users to pay-to-play games."
>
> 注意他的句法：每个案例都用**"X used to dominate because Y; 新进入者通过 Z 重写规则"**这种对称结构。读者扫完五个案例，就理解了框架不是只对 Apple/Google/Facebook 三家成立。

> **[Step 5 — 推导战略含义]**
> "most of these doomed enterprises were based on something other than providing a superior product."
>
> 战略含义是清晰且可操作的：**先建立 superior user experience，再把这个体验漏斗化成对某类客户的独占触达**——这才是长期的护城河。反过来说，所有"只靠控制渠道但产品不够好"的旧巨头都注定被瓦解。这条尺子可以被读者立刻拿去判断任何一个待评估的公司。

> **[Step 6 — 开放收尾]**
> 文章没有给绝对结论，而是把这套"用户优先"的转变称为对消费者和独立创业者来说"welcome"的趋势，邀请读者把这把尺子用到他们自己关心的行业去。
>
> 这就是 Ben Thompson 的经典收尾节奏——**框架在这里成型，但下一篇文章里它还可以被进一步迭代**。这种"it depends / 留给读者继续套"的姿态，是 Stratechery 风格最重要的署名。

## 与原意一致的要点

- **"It depends" 哲学**：Ben Thompson 反复强调，战略没有唯一正确答案。框架是地图（map），不是判决书。一旦你在结尾给出绝对预言，就背离了这种风格。原话见 Moat Map 结尾："there is no one perfect strategy: as always, it depends."（https://stratechery.com/2018/the-moat-map/）
- **Incentives 优先于行为**：核心提问永远是 "Why do businesses do what they do?"。不要停在"他们做了什么"，要解释"是什么激励结构让他们必须这样做"。
- **框架 > 单次分析**：每篇文章的目标不是评论一家公司，而是**沉淀一个能复用到下一篇的工具**。Ben Thompson 的工具箱（Aggregation Theory / Funnel Framework / Moat Map / Hierarchy of Needs / Strategy Credits / Disruption vs Disaggregation）是十年累积的结果，每篇文章都在添砖加瓦。
- **承认前作不完整**：常见开场是"我上周写过 X，但我觉得不够满足"——这种姿态不是示弱，而是邀请读者跟自己一起思考。
- **保留英文术语**：Aggregation / Moat / Funnel / Hierarchy of Needs / It depends / Spectrum 等 Stratechery 标志性术语建议保留英文 + 中文翻译并列（如"Moat Map（护城河地图）"），让读者识别这是 Stratechery 体系内的概念。

## 何时切换走

如果写到一半发现下面任一情况，可能这个框架不对：

- **你只想评论一家公司，不想造图**：那么换 SCQA 或 Paul Graham essay。Stratechery 分析的核心承诺是"沉淀一个可复用框架"，没有这一步它就只是观点文章。
- **你的题材没有清晰的"维度对立"**：如果你找不到至少两个能正交（orthogonal）的轴，强行造矩阵会显得套用。这时候用 Tim Urban Explainer 把概念讲清楚反而更好。
- **你想抒情或讲故事**：Stratechery 风格是冷静的、分析的、几乎没有情绪修辞。如果题材的能量在故事和情感（创业复盘、个人转折、人物传记），用故事化框架更好。
- **题材是工具/方法论教学**：Stratechery 分析的对象是**已经发生的商业事件**，不是"如何做某事"的指南。
