# ContentAny 发布前质量参考门禁

## 用户要求与判定

2026-09-06 用户要求 ContentAny 作为发布前硬性参考，并澄清质量建议不必逐条照改；随后明确“0-20以内是黄金标准，若超过则不准发布”。合并执行：最终整稿的 AI 指数必须在 0%–20%（含 20%）内，同时取得真实质量报告并完成编辑复核。质量建议可有理由地不采纳，数值门槛不可由编辑豁免。这是用户的账号发布标准，不宣称它是微信官方算法或作者身份鉴定标准。

通过条件同时满足：

1. ContentAny 实际检测了拟发布的标题、正文及承载内容的图注，保留了输入与真实输出证据。
2. 最终整稿的实际 AI 指数满足 `0% <= AI 指数 <= 20%`。超过 20%、指数缺失、报告未完成、演示数值或版本不匹配均不得放行。若服务分别提供分段与全文 AI 指数，全部记录，不能挑较低值掩盖另一项超过 20%；AI 密度、原创率等不同指标不替代 AI 指数。
3. 实际报告中的质量问题已经审阅，针对具体问题记录采纳、部分采纳、不采纳或待解决，并说明依据。
4. 没有尚未解决的实质事实、逻辑、原创归属或标题失实问题；涉及用户核心立场等必须本人决定的事项已沿用明确意见或取得决定。
5. 最终内容与报告对应。结论写为“AI 指数达标，已送检且编辑复核通过”，不改写为“ContentAny 官方认证”“保证有流量”或“平台审核通过”。

原作者确认手写、已经授权转载、旧版本达标或编辑认为属于误报，都不能豁免超过 20% 的最终整稿。正文单独检测仅供诊断，不代替包含标题、署名和内容型图注的完整发布版本。不得只在检测输入中删除这些内容、偷偷截取低分片段或多次无改动重测挑最低值。确有问题就保真修订最终稿再送检；不得编造经历、加病句或删掉必要事实限定来压分。

合理的不采纳例子：授权转载被判相似，需要核查署名和授权而不是洗稿；泛化“不要 AI 图片”的建议，不能自动推翻用户已确认的原创场景插图；工具要求添加第一人称体验，但作者没有真实经历，必须拒绝编造。拒绝建议要对应原文与证据，不能用“我不同意”一笔抹掉整份报告。

## 实际运行

官方说明入口：<https://www.aifoxs.com/help/help.html>。2026-09-06 由官网链接核实的检测界面为 <https://cn.aifoxs.com/CheckRepeat>。“AI检测 → AI指数检测”提供分段判断，标题为“多维度内容质量报告”的区域仍可能只有通用说明；“流量预测 → 深度检测”才是本次界面中的正文质量评估入口，分别填写标题与正文。页面默认文本和深度报告是演示数据，明确提示点击检测才会生成真实报告。界面可能更新，每次从当前页面核实，不使用猜测的私有 API。

依赖当前 Host 的原生浏览器能力、可用服务和所需账号权限。通过 Host 已支持的 UI 工具操作；此 Skill 不保存 Cookie、密码，不创建第二连接运行时。后台不可用、要求用户登录、额度不足或收费未获授权时，状态为“未完成送检”，不能绕过。当前用户要求使用 ContentAny 作为常规稿件送检目的；如稿件含非公开敏感信息，上传前仍需确认具体范围，不能把内部笔记、凭证、作者私人信息或整个项目一并送入。

1. 从最终稿整理送检文本：标题、正文、内容型图注及必要署名，不上传 frontmatter、内部编辑备注、文件路径、凭证或图片二进制。保留文本快照与其 SHA-256、源稿路径。只有排版标记变化不影响语义时可复用该输入。
2. 确认当前检测服务、费用/额度和输入范围。将文本填入实际原文框，执行当前界面的检测动作。
3. 等待真实完成状态；核对输入、输出时间与结果。必须排除首页样例、缓存旧稿、未完成状态和截图中的演示数据。只看到“通过”字样而不能确认对应当前输入，不算通过。点击超时先查看页面是否已经开始或完成，不能直接重复提交；重新打开的页面可能恢复旧输入和旧报告，切换样本时核对全部输入框。
4. 保存工具原始报告（导出或页面可见文本）与截图/报告标识；能获取的维度如内容质量、同质化、逻辑、标题、AI 指数均原样保留。不可得项明确注明，不能只摘一个好看的分数。若实际结果只有 AI 概率而没有内容质量反馈，应补做可用的内容评估后再判断。
5. 结合原文、来源与用户意图逐项复核。改动标题、主张、关键事实、论证、结构或内容型图注后重检最终内容；纯 CSS、尺寸、压缩或无语义格式变化不用重复消耗检测。
6. 同一问题连续两轮仍无改善时停止机械循环，说明争议和原因；有充分依据可不采纳具体质量建议，但 AI 指数仍超过 20% 或实质问题仍未解决时保留未通过。不能为了过分数反复洗稿或盲目购买额度。

## Case 内的最小记录

使用当前 Case 的 `qa/contentany-review.md`，复用已有 QA 目录，不建第二套台账。

记录：送检时间与入口、输入文件及 SHA-256、目标平台、原始报告路径/截图/报告标识、实际 AI 指数与 0%–20% 判定、实际可用维度、逐项建议和处置理由、最终内容是否匹配、未解决项、编辑结论。初始状态是“未送检”，指数超过 20% 时是“AI 指数超标，禁止发布”，有报告但待处理是“已送检待复核”，只能满足上方全部条件后写“AI 指数达标，已送检且编辑复核通过”。纯维护或流程演练另标“演练”，不能给真实稿件放行。

事实核对、作者立场、场景化视觉与微信排版检查分别由现有责任 Skill 承担，本门禁不复制它们的清单。报告通过也不新增发布授权；草稿箱、预览、公开发布和群发必须分别如实报告。
