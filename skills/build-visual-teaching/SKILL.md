# 图片与课程制作范式

## 1. 先定材料与讲述逻辑

读完整的相关上下文、原文件、已认可样例和最新反馈，确定受众、问题、范围与交付形式。保留有效正文、真实素材、用户编辑、备注和链接；最新明确要求替换同一对象的旧要求，不让用户重教已有标准。

关键素材、本人观点或模块逻辑未定时，先整理“采用什么、说明什么、怎样关联、形成什么判断、还缺什么”，确认后再生图或改写整套作品。此前可盘点和检索；只访谈资料无法回答的个人取舍，不让用户代做检索，不编造其经历与观点，不把沉默当确认。已有明确 brief、材料和逻辑确认时直接制作；局部文字、对齐、裁切等小修直接落实，仅对新增重要素材或改变本人观点、讲述逻辑的部分补问。

## 2. 从原始来源组织内容

读作者原仓库、SKILL.md 及相关文件、原书、官方文档与真实界面，旧摘要只用于定位。保留关键原意、术语、选择顺序与作者表达，辅以易懂释义；区分原文、教学归纳和个人体验，遵守引用许可与本次来源范围。记录实际采用的来源、版本或日期及直达链接。公开发布时另外核对素材再分发权；可访问、署名或用于教学不自动等于有权公开打包。

核验聚焦主结论、行动风险、明显矛盾、关键精确数据及作者原话/归属。用户亲述、合理低风险的次要体验自然采用，不反复索证、自动加“未核实”脚注或阻塞制作；例如个人描述某次工具使用很快，可作为体验，不能升级成性能基准或产品保证。真实图表、界面与原始 Skill 仍回原始来源。

按整课、模块和重要概念组织总—分—总：问题与位置 → 平实定义、职责、材料和必要边界 → 可据此得出的判断与自然转场。模块框架须说明各部分关系，不能只是术语清单或无根据的单链。按受众决定深度；内容多时分组或拆页，不缩成口号或无法阅读的小字。具体结构、关系表达、正文与讲稿分配见 [讲解结构](references/teaching-depth.md)。

## 3. 沿用足够好的成果，再作必要修改

按 [视觉基准](references/visual-benchmarks.md) 实际查看本次任务提供且允许使用的参考图；参考缺失时先建立新基准，不声称见过未提供的样例。使用讲解角色时另看 [人物参考](references/lecture-persona.md)。保留已认可且适用的页面，能局部改就不整页重做；只有构图无法承载内容、风格明显偏离或用户要求新方向时重做必要部分。

保持清晰大标题、文字主导、充分正文、淡彩与留白。没有指定视觉时，可从白色或浅色背景、粗手绘墨线与少量钴蓝涂鸦开始。讲解角色为可选项，仅使用自有或明确获准的参考，让角色参与提问、指向与提醒；涂鸦不挡字。按受众调整，不固定色板、卡片数、人物出场或每概念页数。

真实原图、截图、书页与作者证据使用原素材像素；生图负责周围视觉，不能代替证据或冒充真实作者。解释图先完成并审校能独立读懂的图内稿，再按 [素材与编辑](references/material-integration.md) 分开提供定稿全文与构图、素材说明，按三层融合制作。代码可用于组装、原生文字、链接与检查；无其他要求时可用 16:9，当前媒介要求优先。

## 4. 检查最终交付物

按 [交付验收](references/delivery-qa.md) 打开并逐页检查最终 PPT 及约定的 PDF、DOCX；预览、抽样或结构验证不能替代最终导出检查。尤其放大追踪人物肩—肘—腕—手的连接与数量，核对中文字、箭头、原图裁切、链接、备注和转场。修复后重新导出并复查受影响文件。

完成全部约定范围，不以样稿代替整套作品。成品不留制作提示或占位语；仅凭实际可打开、已检查的交付物说明完成情况，具体指出真实缺口。

## 反馈后的精简更新

每次反馈后先判断是否有值得复用的新判断，再查已有规则：能复用就引用，能替换或合并就不追加；以最新有效要求清除同对象的旧约束、重复和冲突。只作最小足够的修改，一次性课程参数留在项目；细节按需复用现有引用，不机械新增文件或规则。少是减少冗余与维护负担，不是少讲、少做、省原始素材，或牺牲正确性、安全和验收。
