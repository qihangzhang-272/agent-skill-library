# 叙事策略审计

叙事好坏不是文笔问题，是**是否存在可检测的结构性错误**。先跑反模式快速检测（红旗），再跑拟物化三问（深度结构），最后综合判定。

## 第一轮：反模式快速检测

### 反模式 1：PR 数据污染

**信号**：最强案例用无法独立核实的数字（"百万播放""千万用户""行业第一"），但有更可信的小数据可用（具体互动数、可截图行为、可复现过程）

**检测**：核心数字主张能否被第三方独立验证？这个数字是否在污染一个本来真实可信的故事？

**原则**：可证伪的具体故事 > 不可证伪的宏大数字

### 反模式 2："替代一切"过度承诺

**信号**："一个平台替代所有 X 工具"，同时做 4+ 品类，无法一句话说清定位

**检测**：能否用 "X but for Y" 一句话讲清？不能 → 面太广、焦点太散

**原则**：全家桶 = 每个细分 60 分。专注型竞品每个领域 90 分

### 反模式 3：灵魂问句失效

**信号**：用 "AI 让一切不一样"、"传统行业还没拥抱 AI" 等空洞口号，而非具体可共鸣的反差

**正确结构**：
1. 承认 AI 有效（"个体已被 10x"）→ 把读者放肯定位置
2. 指出组织反差（"公司却没快 10x"）→ 读者也感受到但说不清
3. 暗示未解决环节 → 引出产品定位

**检测**：反差是否包含具体 Nx？反差是否目标用户都已感受到？是否错误把读者放否定位？

### 反模式 4：NOT Positioning 缺失

**信号**：官网/文档找不到"我们不做 X"。所有需求都接

**检测**：团队能说 3+ 个不适合场景？需求超出边界是接还是推荐别家？

**原则**：可发表 NOT 清单 = PMF 训练过、赛道清晰。没有 = 产品定义可能不清

### 反模式 5：设计哲学不一致

**信号**：对外 marketing 说 A、产品体验做 B、内部文档讲 C——三层不通

**检测**：找核心设计选择（"隐性 vs 显性"、"对话 vs 看板"）。检查是否同时体现在 tagline/官网文案 + 产品默认行为 + 团队文档。任一层违和 → 产品成熟度存疑

### 反模式 6：叙事一致性断裂

**信号**：核心主张 24 个月内变 ≥2 次，每次说 pivot 但方向完全不同

**检测**：看不同时期公开描述是演进还是跳变。≥2 次跳变 → 可能未找

到 PMF

**例外**：团队公开承认前作失败逻辑且新方向避开旧方向所有结构性缺陷 = 正向信号

## 第二轮：拟物化与主体错位三问

**触发条件**——定位含以下任一表述时必须运行：
- "AI 时代的 X"、"Agent 版的 Slack/Discord/微信/邮件/会议"
- "Agent IM"、"Agent Team"、"Agent 群聊"、"Multi-Agent 协作"
- "让 Agent 像同事一样协作"

### 问 1：拟物化检验

产品形态从哪个人类协作场景反向投影（Slack/Discord/微信/邮件/工单）？该场景的结构性限制（回合制、单一频道、序列化），Agent 协作是否必须继承？还是只因为模仿人类场景一起带过来了？

### 问 2：主体错位检验

产品宣称解决"Agent 协作"——单人用户场景下需要吗？真实需求是不是"上下文整合（context bus）"或"人类 transcript/控制权"，被错误打包成"Agent 群聊"？

**核心判断**：主体是人类和上下文，AI 只是连接。Agent 中心 ≠ context 中心

### 问 3：环境错位检验

Agent 真实工作环境是什么？产品本身（IM 窗口）还是 Agent 的 terminal/IDE/repo/filesystem？如果是后者——产品是真护城河还是旁观窗口？真护城河应在：
- **上下文聚合层**：连通已有环境（本地文件/历史会话/GitHub/云文档），不是再造空白输入框
- **运行环境中立桥接**：Agent 留原生环境，产品只做消息层
- **跨时间持久身份记忆**：承认情感陪伴/数字生命，叙事要诚实

**额外检验**："那种一个输入框的产品已经太多了，用户面对新输入框就是脑子空空。"上下文保存在日常工作环境——产品应是连通它们，不是再造一个

### 三问判定

- 全通过 = 产品形态认知清晰
- 一问不匹配 = 存在拟物化风险
- 两问以上 = 产品形态可能存在根本设计问题

### 健康度总评

- 健康：无反模式 + 三问通过
- 有风险：1-2 反模式触发，可修正
- 结构性缺陷：3+ 反模式触发，或拟物化两问以上不匹配

### 修正建议

逐条给出，用"建议用 X 替代 Y"格式。

叙事替代参考：
- ❌ "AI 版的 Slack/Discord/微信" → 直接承认拟物化
- ❌ "让 Agent 像同事一样协作" → 把 Agent 强行人格化入人类协作框架
- ✅ "多人 Agent 共享 context bus" → 主体是 context 不是 Agent
- ✅ "Agent 留原生环境，我们只做消息层" → 承认产品是旁观界面
