# Comic Copy For Public-Account Articles

知识漫画不是把文章切成若干结论。它必须让读者看见一个人、一个物件或一种关系发生变化。

## 分镜先写动作

每格先写可见动作，再写文字：

```text
错误：第二格解释“规则只能抓住已知问题”
正确：编辑删掉一句金句；下一版换了另一种句式回来
```

## 允许没有结论的格子

- 一格可以只是翻材料、停顿、等待或发现矛盾。
- 不要求每格推进一个论点。
- 最后一格可以留下仍需继续做的动作，不强制升华。

## 文案密度

- 一格优先只有一个 4–8 字短语或一个气泡，硬上限 10 个中文字符。
- 画面能表达的动作不再由字幕复述。
- 同一页不要同时使用标题、旁白、对白、标签和结论条。
- 对话必须像人在当前场景里会说的话，不像作者借角色讲提纲。
- 每格文字先标注 `Copy role`：`narration`、`dialogue` 或 `none`。
- 连续格子的旁白不要强行写成字数相近、句式对称的排比。

## 文案从场景中长出来

先写场景事实，再写人物此刻需要说的话：

```text
场景事实：编辑在初稿里看到一条没有来源的断言。
错误对白：“AI 能生成文字，但无法替代人的判断。”
可用对白：“这句的出处呢？”
```

前一句是文章论点；后一句会让人物继续查材料。对白只有影响下一步动作时才保留。

旁白只补画面看不见的时间、语境或视角，并压缩成快速短语：

```text
错误旁白：“她正在认真核对三份材料。”
可用旁白：“初稿出来了”
```

动作已经由画面承担，不需要字幕复述。

## 人类氛围从哪里来

- 手正在做什么。
- 人与材料的距离和姿势。
- 桌面上留下了什么。
- 角色忽略、删掉或重新拿起了什么。
- 时间和劳动如何被看见。

不要靠咖啡、深夜、皱眉或凌乱桌面单独伪造真实感；这些元素只有参与叙事时才使用。

## 避免四格公式

默认禁用：

1. 问题出现
2. AI 分析
3. 人类顿悟
4. 金句结论

如果四格可以直接替换成四个流程框，它还不是漫画。

## 单幅知识漫画解释图

这种形式适用于：正文里有一段关系需要快速看懂，但普通概念插画只能制造气氛，架构图又会把公众号写成技术文档。

固定结构：

1. **视觉中心讲逻辑**：用人物、图标、大小、聚散和位置呈现一个关系；不把正文拆成一排卡片。
2. **侧边角色给入口**：角色指向、观察、核验或追问，只说一句影响阅读方向的话。
3. **短语来自语义源**：标签优先直接取自 `04-revised.md` 的 2–10 字短语；不得先自行总结出新逻辑，再把新词塞回图片。
4. **解释在图外完成**：一张图讲不完的条件、例外和来源放进 caption，不用小字填满画面。

### 角色不是装饰

- 去掉角色后，如果画面完全不受影响，说明角色只是贴纸；改成让角色指出矛盾、边界或阅读顺序。
- 角色不能站在技术框图旁复述标题，也不能每张图都做同一个“托腮思考”动作。
- 同一篇文章使用固定角色参考图，动作随 Viewer job 变化：解释、追问、核验、确认或退后观察。

### 中央视觉不是架构图

- 可以使用少量图标、分组和空间关系，但默认不用组件框、泳道、箭头网络和 UI 卡片。
- 关系优先靠靠近/远离、大小变化、共同参与、人物动作和前后景表达。
- 如果一张图必须依赖箭头才能读懂，先判断是否应改回 diagram；不要假装成漫画。

### 文案上限

- 每张图优先 1 个气泡，气泡 4–10 字。
- 主标签 3–5 个，每个 2–10 字。
- 需要超过 5 个标签时，只有读者必须同时核对这些条目才保留，否则拆图或移至图注。
- 所有允许文字在 `05.5-visual-plan.md` 的 `Exact text` 中逐条列出；生图工具不得临场补词。

## 与 Baoyu Comic 的边界

本文件与 `visual-copy-desk.md` 负责漫画的 `Viewer job`、动作、`Copy role`、候选文案、允许文字与情绪节奏。`baoyu-comic` 负责角色表、正式 storyboard、页面 prompt、角色一致性和图像生成。
